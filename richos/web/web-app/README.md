# The phone client's reference modules

`richos/web/web-app/` held the phone web page (a PWA) that the RichOS desktop app served to a
phone's browser. **The web page was retired on 2026-10-30** (CEO: *"yes, the phone web page needs to
be retired now"*). The native RichConnect apps, `richos/mobile/native-ios` and
`richos/mobile/native-android`, replaced it. The Mac no longer serves anything from this directory:
a browser that opens the old address gets a plain "Use the RichConnect app" page and a phone that
had installed the page is sent a service worker that removes it
(`richos/app/src-tauri/src/phone/routes.rs`, `RETIRED_PAGE` and `RETIRE_WORKER`).

What is left here is not the page. It is code other parts of RichOS load:

| | |
|---|---|
| `lib/api.js`, `lib/queue.js`, `lib/thread.js`, `lib/inbound.js`, `lib/fingerprint.js`, `lib/wordlist.js`, `lib/pcm.js` | **the reference client.** The protocol conformance corpus both native apps must pass is generated by running these modules (`richos/mobile/conformance`, which records them by path in `vectors/index.json`). The review mock (`richos/mobile/review-mock`), the Mac's word-list test (`phone/ca.rs`) and the iPhone core's word-list test read them too. |
| `lib/link.js`, `lib/connection.js`, `lib/follow.js`, `lib/notification-target.js`, `lib/voice.js` | shared with `richos/mobile/core` |
| `bin/make-icons.js` | the icon resizer the native iPhone app's `Release/make-app-icon.cjs` loads |
| `test/` | Node checks of these modules and `stub-mac.js`, the stand-in Mac the native lab (`mobile.mjs lab serve`) and the backfill check use |

The directory keeps its path because the corpus, the native apps' comments and their tests name
these files by it.

A change to a reference module changes what the native apps are held to: regenerate the corpus
(`node richos/mobile/conformance/generate.mjs`) and keep both native apps passing it.

## Running the checks

```
node --test test/*.test.js     # Node only, no browser, no dependencies
```
